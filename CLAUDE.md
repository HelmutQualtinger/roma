# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page Three.js 3D model of central Rome: a 3 × 3 km area around the Colosseum, built from OpenStreetMap data and SRTM terrain. It contains a procedural Colosseum, a procedural Vittoriano (Altare della Patria) and an animated bike ride of 6.1 km: Piazza Venezia → Via del Teatro di Marcello → Circo Massimo → Via di San Gregorio → around the Colosseum (south, east, north) → Via Cavour → Termini (Piazza dei Cinquecento) → Piazza della Repubblica → Via Nazionale → back to Piazza Venezia, drawn on the ground as a neon line. During the ride a HUD shows gradient, speed, power and altitude. The UI is available in German, English, Italian and French: the `I18N` table in the classic script before the module holds every string. Static elements carry `data-i18n` keys, and dynamic text uses `tr()` or `setT()`. The language comes from `?lang=de|en|it|fr`, then the saved choice (`localStorage`), then the browser language, and falls back to German.

## Commands

Open the page with `open roma3d.html`. It needs no server: `scene.js` is a classic script and Three.js r0.165 loads from jsDelivr via an importmap.

Regenerate the scene data. Run the steps in this order, because each one rewrites `data/scene.json` and `scene.js`, and `process.py` drops the keys the later steps add:
```
cd data && python3 process.py && python3 route.py osm.json scene.json ../scene.js && python3 terrain.py
```
`terrain.py` needs numpy and Pillow, and reads the Terrarium elevation tiles in `data/tiles/` (zoom 15, listed in `tiles/list.txt`). `osm.json` is a raw Overpass `out geom` dump and is the only input to `process.py`. It holds the buildings, building parts, highways, landuse, leisure and historic elements in the bbox 41.8761,12.4734,41.9043,12.5110. The Overpass API answers 406 to browser user agents, so use a plain client name.

To check visually without a GPU, take a headless Chrome screenshot. The URL hash picks a view (`#ge`, `#close`, `#top`, `#venezia`). `?t=<seconds>#ride` starts the ride and fast-forwards it by that many seconds:
```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist --user-data-dir=<tmp> --window-size=1400,900 --virtual-time-budget=60000 --screenshot=<out.png> "file://$PWD/roma3d.html?t=60#ride"
```
Add `?info` to the URL to log `renderer.info.render` (draw calls, triangles) once on the third frame. Under headless virtual time the FPS counter reads 0 and frame `dt` can be 0, so never let displayed values depend on a non-empty integration loop.

## Data pipeline (`data/`)

- **`process.py`:** projects lat/lon to local metres. The origin is the Colosseum centroid (OSM relation 1834818). x = east, y = north, `KX = 111320·cos(41.8902°)`, `KY = 110574`; the JS uses the same constants. It emits compact `buildings`, `roads` and `areas` (flat `[x,y,…]` rings). It also emits `colosseum.angle`, the major-axis angle fitted from the footprint, and `origin`. Facade and roof colours come from OSM tags, or from a hash-seeded palette.
- **`route.py`:** Dijkstra over the OSM highway graph. Car roads cost ×1 and pedestrian/foot ways cost more, so the ride stays on asphalt. A waypoint can name a street, as `(x, y, 'Via Cavour')`, and then snaps only to that street's nodes, so the path can't slip into a parallel alley. A waypoint `(x, y, None, False)` may also snap to a footway. It strips U-turn spikes and moves the seam of the closed loop off any dead-end stub, so a new lap never starts with a U-turn. Then it stores `route`. `placeName()` in the page names the legs for the HUD, splitting the legs at `S_COL` and `S_TERMINI`.
- **`terrain.py`:** turns the SRTM DSM into a DTM-like heightmap in these steps:
  1. A morphological opening removes buildings.
  2. A gaussian blur smooths the result.
  3. The terrain is clamped under the Vittoriano footprint.
  4. A level platform is made around the Colosseum.
  5. Laplacian-smoothed street heights are burned back in, because SRTM shows the excavated fora rather than the road surface.

  The result is stored as base64 Int16 decimetres in `terrain` (8 m grid, ±1700 m). The OSM area is ±1500 m (`HALF` in `process.py`), so it reaches Termini and Piazza della Repubblica. The 30 Terrarium tiles cover the terrain.

## `roma3d.html` architecture

Everything is one module script, split into sections marked `// ---------- … ----------`. Key cross-cutting conventions:

- **Coordinates:** data coords (east, north) map to Three as `(x, height, -north)` via `P3()`. Procedural groups use their own local frames and are placed with `position`/`rotation.y`:
  - Colosseum: u along the major axis, v along the minor axis.
  - Vittoriano (`VIT`, `vitLocal()`): X along the facade, D (local z) toward the back.
- **Heights:** `asl(x,y)` samples the heightmap. `gh(x,y)` returns the render height relative to the Colosseum (`BASE`), faded to `HEDGE` at the border. Everything placed on the ground must use `gh`: buildings (base `hc`/`hb`), densified road ribbons (`+0.3`), trees, labels, the bike and the camera.
- **Geometry:** `Geo` accumulates non-indexed triangles with vertex colours and UVs. Materials are `DoubleSide` and normals come from `computeVertexNormals`, so winding doesn't matter. `Tiled` buckets geometry into 250 m tiles so that the camera and shadow frustum culling work. City meshes must stay tiled, and trees are per-tile `InstancedMesh`es.
- **Textures:** all generated on canvases at startup (facades, shops, masonry, Colosseum arcade bay, marble). Land use (parks, archaeological areas) is painted onto the terrain texture `LAND`, not built as geometry.
- **Shadows:** `renderer.shadowMap.autoUpdate = false`. `setShadow('overview')` renders an 8K map over the whole area once. `setShadow('ride', center)` renders a 4K map over ±220 m that follows the rider, snapped to the texel grid. Anything that changes the scene must request `renderer.shadowMap.needsUpdate`.
- **Pantheon and Fontana di Trevi** (section after the Arch of Constantine) are procedural like the Vittoriano, in local frames (`lframe()`: x along the facade, z towards the back, front at −z) taken from the OSM footprints. The OSM building `Pantheon` is skipped in the building loop; `Palazzo Poli` stays, but at 24 m, because its south front carries the fountain. They use their own random stream `lrng()`, so they don't shift `rnd()` for everything after them. Helpers: `lathe()` (surface of revolution, optional z scale), `slab()` (sloped beam), `inscription()`/`plaque()`.
  - Pantheon: rotunda (brick zones, cornices, stepped rings, lead dome, open oculus with dark interior), intermediate block, portico with 16 columns, Agrippa's inscription, pediment, the brick block at the back, and the Fontana del Pantheon with the Macuteo obelisk.
  - Trevi: proportions measured on Wikimedia Commons photos (front panorama; 49.15 × 26.3 m). Giant order over the whole front (capitals 14.3–15.6 m, entablature to 18 m), four columns at ±5.3 / ±10.85 m, exedra 2.05 m deep (deeper would cut into the palace wall) with Ionic column pairs and a diamond-coffered half dome (`LM.coffer`), Oceanus on his shell, Abundance and Salubrity, reliefs, frieze and attic inscriptions, attic statues, balustrade and the papal arms; wings with three bays (shuttered windows, triangular and segmental pediments, balconies, attic windows); the reef of jittered travertine slabs (`rock()`, `rTop`/`rDepth`, spur on the viewer's right), sea-horses with fish tails (`seaHorse()`, restive one on the viewer's left) and tritons (`triton()`), the two-tier central cascade, curtains at the reef front, the basin with water (`LM.water`) and falls (`LM.fall`); `waterStep(dt)` in the animation loop scrolls both textures. Figures are built from tapered tubes (`limb()`, `chain()`, `statue()`). In the local frame +x is the viewer's LEFT (west), seen from the piazza.
  - Both are floodlit at night (`LM.stone`, `LM.brick`), have labels and views (`VIEWS.Pantheon`, `VIEWS['Trevi-Brunnen']`), and keep-out zones (`KEEP_OUT`, `inLandmark()`) that keep street lamps out of the buildings and the basin.
- **Ride:** `route` is a CatmullRom curve built from `S.route` with rounded corners.
  - The rider is a Roman gladiator, loosely after the murmillo, on the road bike. It has a bronze galea with brim, face grille and red crest, a manica on the right arm, a greave on the left shin, a balteus, a loincloth, sandals and a round shield on the back. The static parts are merged per material; the legs are moved by `pedal()`.
  - `placeBike` derives the heading from a ±2 m chord, smooths it, and sets lean (v²κ/g) and pitch (grade).
  - `rideStep` integrates speed from power: `PHYS`, `powerAt()`, 190 W target, coasting and braking near `vMax`.
  - The camera is rigidly offset from the rider. Only its yaw trails the heading, so the distance stays constant.
  - A procedural lion (`lion`, `lionStep(sim)`, state in `LION`) gallops 3.4–4.6 m behind the rider, offset ~0.75 m sideways. Its legs use two-bone IK with paws planted in stance (rotary gallop, duty factor falls with speed). The fur has three parts:
    - shell fur: `addShells()` adds an `InstancedMesh` of 6 shells per furred mesh, using an object-space hash and discard. Shells are hidden when the camera is more than 30 m away.
    - mane, chest, elbow and tail clumps: alpha-tested ribbons (`hairGeo`, `mHair`).
    - face details: whiskers, lips and rimmed eyes.

    The lion is excluded from the static matrix freeze. The chase camera sits 9.5 m back so both stay in frame. The drone camera circles the rider and the lion once every 36 s (`ride.orbit`). `ride.dr` blends between the chase and drone cameras, and `?drone` starts the ride in drone mode.
  - The elevation and grade profiles (`PROF`/`GRADE`, 2 m samples) feed the HUD (`#stats`, `#prof` canvas).
  - The road ribbons take their height at their corners (edges, ≤ 6 m apart), so in a hollow the asphalt lies above `gh` at the centre. `ROUTE_EX` (per 2 m route point, `routeEx(s)`) lifts the neon line to the highest mean of plausible quad corners there; the rider, the lion and both ghosts are lifted by the same amount so they stay on the line.
  - Camera collision: the building loop fills a 40 m grid `BLD` of footprints with bottom and top. `camClear()` walks from the orbit centre outwards in 0.5 m steps and stops before the first point that `camBlocked()` reports (inside a footprint or closer than `CAM_PAD` = 1.2 m to a facade, the Colosseum, the Vittoriano). `ride.camF` pulls in at once and lets out slowly; it applies to the chase and the drone camera.
  - Ghost and pacemaker run in the normal ride too, through the same `liveLap()`/`refStep()`/`gapHud()` code. The panel labels them only as **Last Round** (`#sGhost`, red `ghost`) and **Pacemaker** (`#sRef`, blue `refRider`, power from `#refPower`, always shown in the toolbar) in every language. The normal ride, like the live mode, goes on lap after lap (the HUD shows the lap and the last lap time). From lap 2 the red ghost replays the previous lap. A fresh `startRide()` outside live mode calls `resetRace()` but keeps `LIVE.prev`.
- **Live-Ergometer mode:** this mode runs only when the ergometer server in `~/Ergometer` serves the page: `uv run ergometer.py --panel --site ~/roma`, then open `http://127.0.0.1:8050/site/roma3d.html` (add `?live` to start the mode at once).
  - `#liveBtn` is always shown. Served from anywhere else (GitHub Pages, another web server, `file://`), the endpoints fail quietly and the mode runs as the demo fallback, with no error message. Without a server, `livePoll()` retries only every 5 s.
  - `startLive()` starts a manual run on the server (`/profile` `{action:'start'}`), so the ride is logged. `stopLive()` stops it.
  - `livePoll()` runs every 0.5 s. It reads the power, cadence and resistance level from `/data`. It sets the level directly through the server's `/resistance` endpoint.
  - The level is the mean gradient from the rider to `RES_AHEAD` = 100 m ahead (`gradeAhead`), scaled linearly onto `RES_LO`–`RES_HI` (7–15). The scale runs from the route's 2nd percentile of that gradient (`GA`) to its 98th. With 20 m the level changed about every 10 s.
  - A new level is sent only when the scaled value is more than 0.75 levels from the current one, and at most every 3 s. Pause sends `RES_LO`.
  - `rideStep` integrates the measured power (`LIVE.power`) with the weight from `#weight` (`PHYS.m`, saved in `localStorage`). The pedals turn with the real cadence. The race (`LIVE.started`) starts with the first pedal stroke, a sample with cadence > 0 that arrives after the start. Before it, the rider waits at the start line, nothing moves and the HUD says so; in the demo it starts at once. `resetRace()` puts everything back to the start. Returning from the demo to live starts a new race, so demo laps never become the ghost's reference.
  - The route is a closed loop, so the ride wraps into laps. `liveLap()` records `[lap time, s, crank angle]` every 0.2 s. From lap 2 on, `ghost` (a red translucent clone of `bike`, with its own legs and wheels) replays the previous lap. `#sGhost` shows the time gap.
  - Reference rider (`refRider`, blue, from `makeGhost()` like the red `ghost`): from the race start, `refStep()` integrates the same physics and weight at the constant power `#refPower` (`REF.P`, saved in `localStorage`). It records its total distance in `REF.trace`, and the rider's in `LIVE.race`, as `[race time, distance]`. `#sRef` shows the exact time gap in both directions. At every new lap the reference is put back level with the rider, at the rider's speed, and both traces restart, so the gap is per lap. Before the start, it waits visibly at the start line. `placeGhost()` puts both ghosts beside the line: red 0.7 m, blue 1.4 m.
  - `#liveSave` downloads the ride since the race start as `roma-ride-<start>.csv`. `logRow()` writes one row per second of race time, with pauses excluded. The columns are: local time, lap, distance, speed, power, cadence, resistance, heart rate, gradient, altitude, lat/lon, gap to the ghost and to the reference, reference power, weight, and live/demo. `resetRace()` clears the log.
  - Demo fallback (`setDemo()`, `LIVE.demo`, `body.demo`): if the ergometer is not connected, if 30 s pass without samples, or if the server is gone, the simulated rider of the demo ride does the laps at the speed of the time-lapse slider. No resistance is sent, and the ghost still works. The first sample with cadence > 0 switches back to live.
  - Space pauses. A ghost whose lap is over disappears. `?live&t=<s>` fast-forwards with the first measured power (test hook).
  - To test without the bike, import `ergometer.py`, set `SITE["dir"]` and `CONTROL["range"]`, call `start_panel(8060, False)`, and append fabricated `SAMPLES` (power = `table_power(level, cadence)`). For `/resistance`, also set `CONTROL["client"]`, run an asyncio loop in a thread as `CONTROL["loop"]`, and replace `set_resistance` with a fake.
- **Rendering cost:** the city uses `MeshLambertMaterial` (`lam()`). `MeshStandardMaterial` (`mat()`) is kept only for marble, gold and bronze. There is no logarithmic depth buffer; instead the camera near/far and the fog switch between overview (3–9000 m) and ride (0.5–2600 m), and roads use `polygonOffset`. Static scene objects have `matrixAutoUpdate` off. Only the bike, the sun and the camera update their matrices.
- **Night mode:** `setNight()` swaps the sky, fog and lights, and switches on emissive maps: lit windows and shops on `MAT.win`/`MAT.shop`, a floodlit Colosseum on `MAT.col`, and the Vittoriano and arch marble on `MV.m`. Street lamps are instanced every ~32 m along car roads, but never on a carriageway: `onRoad()` rejects spots within any road's half width + 0.8 m (before, 40 % stood on crossing roads and the riders went through them), with additive light pools on the ground. Each window switches on and off on its own after an exponentially distributed time (mean `WIN.mean` = 100 s). `winStep()` toggles random slots of the 256 × 256 state texture `WIN.tex` as a Poisson process with rate N/mean. The `MAT.win` shader hashes the window cell `floor(uv·4)` to a slot, and `walls()` gives every facade whole-tile UV offsets so that its cells are unique. Six real `PointLight`s hop to the lamps nearest the focus every 10 frames (`nightStep`). The star dome follows the camera. During the ride a headlight (`NIGHT.spot`, a SpotLight in `NIGHT.objs`) shines from the camera onto its look point, so the rider and the lion stand in a pool of light; outside the ride it fades to intensity 0 instead of being switched off, because changing the number of lights recompiles every material. `NIGHT.objs` is dynamic, so it is excluded from the static matrix freeze.
- **Fisheye:** `drawFrame()` renders the scene into `fishRT` with an overscanned field of view and warps it to the screen (`fishMat`, centre magnification 1/(1−k)); `fishScreen()` maps label positions through the same warp, and `?nofisheye` turns it off. In the overview k = `FISH.k` = 0.2; during the ride `FISH.kRide` = 0.4, so the race in the centre is larger. `FISH.cur` eases between the two, and in the ride the target is rendered `FISH.ss` = 1.2 times larger so the magnified centre stays sharp, but only on screens without Retina (`PR_MAX` < 1.5). On a Retina screen it would defeat the adaptive pixel ratio: 1.25 × 1.2 costs as much as 1.5. The target uses 2 MSAA samples. Measured at 2800 × 1800 in the ride: 4 samples and ss 1.2 gave 31 fps, 2 samples and ss 1 gave 55–60; shadow updates cost almost nothing, the lion ~3 fps, the fisheye pass as a whole ~20 fps.
- **Click navigation:** outside the ride, a click (pointer moved ≤ 6 px, < 450 ms) raycasts the scene and tweens the target to the hit, keeping the viewing direction at 0.6 × the distance (80–600 m). With the fisheye on, the click is mapped through the shader's forward warp and cast from `overCam`; hits on invisible, route, star-dome and transparent no-depth objects are skipped.
- **Performance:** adaptive pixel ratio (between 1 and the device pixel ratio, targeting about 60 fps) and the FPS counter (`#fps`) live in the animation loop. It steps down after two slow 60-frame windows (< 48 fps) and up after five fast ones (> 58 fps), ten during the ride. The ride must step up too, because it runs lap after lap: otherwise one slow stretch left it at ratio 1 for good. A ratio that was too slow (`perf.cap`) is not tried again for 60 s, so the resolution doesn't oscillate. The screenshot buttons render at 4K/8K with pixel ratio 1.
